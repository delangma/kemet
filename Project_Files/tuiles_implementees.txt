AUDIT DES TUILES POUVOIR — RÈGLES RÉELLEMENT IMPLÉMENTÉES DANS LE CODE
========================================================================
Ce fichier liste, pour CHAQUE tuile pouvoir du jeu, ce que le code fait
RÉELLEMENT (pas ce que dit la règle papier). Objectif : vérifier tuile par
tuile que le comportement codé correspond à la règle voulue.

Sources analysées : src/constants/powerTiles.js, src/constants/creaturePowers.js,
src/components/Game/GameScreen.jsx, src/components/Game/NightModal.jsx,
src/components/Combat/CombatModal.jsx, src/components/Combat/DawnModal.jsx,
src/ai/aiPlayer.js, src/utils/vp.js, et modales associées (CreatureEquipModal,
IdDraftModal, IdRefreshModal, CombatCardSwapModal, PyramidEvolveModal).

/!\ DawnModal.jsx ne référence AUCUNE tuile pouvoir : aucune tuile n'interagit
    avec la phase d'Aube.

------------------------------------------------------------------------
PROBLÈMES TRANSVERSAUX REPÉRÉS (à vérifier en priorité)
------------------------------------------------------------------------

1) [CORRIGÉ] PROTECTION PLUIE DE FEU : hasFireRainProtection() est
   désormais appelée (via le helper isFireRainProtected() dans
   GameScreen.jsx) à chaque ciblage de Pluie de Feu — carte ID ET bonus
   Ta-Seti, humain ET IA. Une troupe protégée (tuile "Protection pluie de
   feu", valable pour toutes les troupes du joueur, OU Dévoreuse des Mondes
   stationnée dans la zone) ne peut plus être sélectionnée comme cible.

2) [CORRIGÉ] ACHAT PAR L'IA : le code d'achat de tuile de l'IA
   (GameScreen.jsx, cas "buy_red"/"buy_blue"/...) applique désormais les
   mêmes bonus ponctuels à l'achat que le joueur humain : unitsOnPurchase
   (Recrutement +2, Renforcement 4 unités, placement immédiat dans la
   cité), reserveOnPurchase (Unité supplémentaire), idCardsOnPurchase (+1
   carte ID, Momie), taSetiAdvanceOnPurchase (Avancée sur taseti),
   pyramidUpgradePending gratuit (Augmentation pyramide), et
   idRefreshPending (Draft ID). Les effets nocturnes récurrents
   fonctionnaient déjà pour l'IA (NightModal traite tous les joueurs
   uniformément).
   Note résiduelle : idRefreshPending (Draft ID) est bien posé pour l'IA
   à l'achat et chaque nuit, mais aucune logique de RÉSOLUTION IA
   (choix des cartes à défausser/piocher) n'existe — le flag reste donc
   posé sans être consommé côté IA tant que cette décision n'est pas
   implémentée séparément.

3) [CORRIGÉ] JETONS JP "prescience" et "legion" : désormais branchés.
   - "prescience" (JP_prescience / JP_ID_combat) : si un prêtre portant ce
     jeton se trouve dans la zone de combat, déclenche la même révélation
     anticipée de la force adverse que la tuile "Préscience" (vérifié aux
     4 points de déclenchement de combat : téléportation, déplacement
     normal x2, IA).
   - "legion" (JP_legion) : getZoneMaxUnits() accepte maintenant
     boardPriests et accorde +2 unités max, mais UNIQUEMENT dans la zone
     où se trouve le prêtre porteur (contrairement à la tuile "Légion"
     qui s'applique à toutes les zones du joueur). Les 3 points d'appel
     (GameScreen.jsx x2, board.jsx) passent désormais boardPriests.
   Seuls defenseVictoryVp, replacementUnit et wallPass restaient déjà
   branchés par ailleurs (movementBonus l'était aussi).

R_1_1 — Déplacement (niv.1, coût 1, permanent)
  - +1 point de déplacement par tour, cumulé avec "Furie Bestiale" (même
    compteur, voir N_4_3). GameScreen.jsx computeMovePoints().

R_1_2 / R_1_3 — Force en attaque (niv.1, coût 1 — 2 exemplaires marché)
  - +1 force uniquement quand le possesseur est attaquant
    (POWER_TILE_COMBAT_BONUSES). Un joueur ne peut posséder qu'un seul
    exemplaire (restriction par nom à l'achat) → jamais cumulable à +2.

R_1_4 — Réduction Téléportation (niv.1, coût 1, permanent)
  - Coût de base de téléportation : 2→1 Ank (avant "Réduction d'ank" /
    "Téléportation facile"). computeTeleportCost().

R_2_2 — Passe muraille (niv.2, coût 2, permanent)
  - Permet d'entrer dans une cité ennemie sans arriver d'une zone adjacente
    au premier pas (contourne la règle de "Muraille"). hasParseMuraille().
    Même effet obtenu via le jeton doré R_4_1 ou un jeton de prêtre
    JP_passe_muraille.

R_2_3 — Goutte de sang (niv.2, coût 2, permanent)
  - +1 sang (dégât) dans tous les combats, attaquant ou défenseur.

R_2_4 — Avancée sur taseti (niv.2, coût 2, permanent)
  taSetiAdvanceOnPurchase:1, taSetiAdvancePerNight:1
  - Achat : +1 immédiat à taSetiNightAdvancePending.
  - Chaque nuit : +1 de plus, cumulatif avec d'autres exemplaires/tuiles.
  - Consommé via le bouton "🌙 TS" (MyZone.jsx → GameScreen.jsx).
  - IA : le +1 d'achat n'est PAS appliqué (voir point transversal #2), le +1
    nocturne s'applique quand même.

R_2_5 — Carte Sang 3*3 (niv.2, coût 2, permanent, combatCardSwapNewId:9)
  - À l'achat : remplace une carte combat du deck par la carte #9
    (Force3/Sang3/Bouclier0). Humain : choix via CombatCardSwapModal. IA :
    remplace automatiquement sa carte la plus faible. Aucun effet passif
    continu, uniquement une modification ponctuelle du deck.

R_2_6 — Téléportation facile (niv.2, coût 2, permanent)
  - -1 Ank sur le coût de téléportation (cumulable avec R_1_4/"Réduction
    d'ank"). Permet aussi de LANCER une téléportation depuis un obélisque
    du plateau principal (T1/T2/T3/TB/D12/D23 — rien à voir avec Ta-Seti),
    pas seulement depuis une cité : permet donc d'enchaîner obélisque →
    obélisque, comme le fait nativement le Sphinx Volant. Via
    teleportFacileActive dans board.jsx (canTeleportFromHere).
    (Le Temple Bleu est bien un obélisque dans ce jeu — TELEPORT_TARGETS
    incluant "TB" est donc correct, malgré une mention contraire trouvée
    dans un document de règles annexe.)

R_2_1 — Phoenix : créature, voir section CRÉATURES.

R_3_1 — Scarabée : créature, voir section CRÉATURES.

R_3_3 — Point Rouge Majeur (niv.3, coût 3, type vp, vpOnPurchase:1)

R_3_4 — Force par ID (niv.3, coût 3, permanent)

R_4_2 — Scorpion : créature, voir section CRÉATURES.

R_4_3 — Jeton gris (niv.4, coût 4, jeton)
  - Un seul jeton gris par joueur (isGrayTokenTile, restriction à l'achat).
  - Chaque nuit : tokens = 6 au lieu de 5 (NightModal.jsx). Aucun effet

  - [CORRIGÉ] Ce 6e jeton n'est PAS un tour indépendant comme les 5 de base :

BI_3 — Pyramide Niv.3 (Bleu niv.2, coût 4, secondaire Blanc niv.2)
  - Implémenté dans src/utils/vp.js computeTempVP() (PAS dans les fichiers

    simultanément (pas seulement la couleur liée à la tuile). Cette

    départage du vainqueur final (pendingEndAtNight, NightModal.jsx).
  - Bizarrerie structurelle à vérifier : le code lit

    d'ennemi" regarde la mauvaise zone.

getCombatResult(). Toute créature achetée doit être équipée sur une troupe
via CreatureEquipModal.jsx (action gratuite, sans jeton) sauf mention
contraire.

  bonus de force propre), nullifiesEnemy:true — en combat, annule TOTALEMENT
  les bonus (force/boucliers/sang) de la créature adverse dans cette zone
  (annule aussi le bonus fleuve du Kraken adverse, puisque ce bonus est
  neutralisé dès que "nullified" est vrai pour ce camp).
  [CORRIGÉ] Annule aussi les POUVOIRS SPÉCIAUX de la créature adverse, pas
  seulement ses stats : nullifiesEnemyShields (Méduse) et
  nullifiesAllBloodExceptCards (Minotaure) adverses ne s'appliquent plus si
  je possède un Serpent (getCombatCreatureBonus, flag myHasSerpent). Le
  2e PV de la Dévoreuse des Mondes (onWinBloodBonus) était déjà
  correctement annulé par winnerNullified, aucun changement nécessaire là.

Notes sur le cumul des annulations (getCombatCreatureBonus) : si l'un des
deux emplacements de créature d'un joueur (activé par Chiron) porte un
flag d'annulation, il s'applique ; nullified/shieldsNullifiedByEnemy/
creatureBloodNullifiedByEnemy sont chacun calculés en OR sur les deux
emplacements adverses.

Flags morts/inutilisés annexes (non liés à une entrée POWER_TILES, mais
pertinents pour l'audit) : nullifiesEnemyCreatureBlood est référencé dans
getCombatCreatureBonus mais aucune créature de CREATURE_POWERS ne le pose
(inaccessible sauf via la branche OR séparée nullifiesAllBloodExceptCards).
Les champs prescience et legion de getJpTokenFlags() sont calculés pour
les jetons de prêtre Ta-Seti mais jamais lus par aucun code consommateur
(seuls defenseVictoryVp, replacementUnit, wallPass et movementBonus sont
réellement branchés).
